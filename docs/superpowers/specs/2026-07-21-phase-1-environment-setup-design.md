# Phase 1 — Environment Setup (Design)

**Date:** 2026-07-21
**Phase:** 1 of the IslandKit build plan (see `CLAUDE.md`)
**Status:** Approved for implementation planning

## Goal

Turn the near-empty repo into a working pnpm monorepo where the `expo-island-kit`
native module is linked into an example Expo dev-client app, prebuilds, and runs.
Prove the environment end to end. **No preset logic** (that's Phase 2).

## Starting point (verified)

- Repo contains only: `CLAUDE.md`, `islandkit-full-documentation.md`, root
  `package.json`, `pnpm-workspace.yaml`. No `packages/`, no `apps/`.
- Git repo initialized fresh on `main` (the "Phase 1 commit" referenced in
  CLAUDE.md did not actually exist).
- Toolchain present: Node 25.8, pnpm 10.17, Expo CLI 11.13, Xcode 26.0.1
  (Dynamic Island simulators available), CocoaPods 1.17, Ruby 4.
- Known wrinkle: `watchman` binary is broken (missing `libfmt` dylib). Metro runs
  without it; recommend `brew reinstall watchman` but non-blocking.

## Decisions

| Decision | Choice |
|---|---|
| Scaffold method | `create-expo-module` into a temp dir, then reshape into the workspace |

## Build sequence

1. **Root config** — `.gitignore` (done), keep `pnpm-workspace.yaml` (`packages/*`,
   `apps/*`). Give the root `package.json` a sane name/private flag.
2. **Generate module** — `create-expo-module` in a temp dir; move its module output
   into `packages/expo-island-kit`. Rename the generated module/view classes to
   IslandKit naming where trivial, but **keep the generated class name the module
   registers under** if renaming risks breaking the bridge (per CLAUDE.md: "match
   whatever class name create-expo-module generated — don't rename it").
3. **Trim to minimal** — strip generated demo props/views down to a module that
   compiles and exposes one trivial function (e.g. `isSupported()` returning a
   bool / a hello value) so we can confirm the JS↔native bridge works without
   any preset code.
4. **Example app** — create `apps/example` as an Expo app, add `expo-dev-client`,
   depend on `expo-island-kit` with `workspace:*`, set `bundleIdentifier`.
5. **Install & typecheck** — `pnpm install` at root; confirm the package builds
   (`expo-module build` / tsc) and the app type-checks against it.
6. **Prebuild + simulator run** — `expo prebuild -p ios` in `apps/example`, then
   build/boot on an iPhone 16 Pro simulator; confirm the app launches and a call
   into the native module returns.
7. **Physical-device hand-off doc** — a short checklist: open the workspace in
   Xcode, select the app target, "Automatically manage signing" → Personal Team,
   confirm the unique bundle ID, then `expo run:ios --device`.

## Explicitly out of scope for Phase 1 (guardrails)

- No Now Playing (or any) preset — Swift attributes, SwiftUI views, or TS preset API.
- No `@bacons/apple-targets` widget extension target.
- No App Groups capability/entitlement anywhere.
- No Push Notifications capability, `aps-environment`, or push-token code.
- No `appleTeamId` in `app.json`; no hardcoded team ID in code. Signing stays manual.
- No Android code or config.

## Definition of done

- [ ] `pnpm install` succeeds at the workspace root; `expo-island-kit` resolves inside `apps/example`.
- [ ] `packages/expo-island-kit` builds (TypeScript emits; podspec valid).
- [ ] `apps/example` type-checks against the workspace package.
- [ ] `expo prebuild -p ios` succeeds and the native module is linked in the Pods project.
- [ ] The example app builds and boots on an iPhone 16 Pro simulator, and a trivial call into the IslandKit native module returns a value to JS.
- [ ] A physical-device signing checklist is written for the developer to run once.
- [ ] No App Group / Push entitlements and no `appleTeamId` were added.

## Risks / open questions

- **Watchman broken** — if Metro misbehaves, reinstall watchman or set
  `WATCHMAN_DISABLE`. Non-blocking for the build itself.
- **create-expo-module template drift** — the generated template on current Expo
  may differ from the documented `src/` + `ios/` shape; we adapt to whatever it
  emits rather than fighting it.
- **Simulator ≠ full DoD** — CLAUDE.md's Phase 1 DoD says "runs on a physical
  device." The simulator run proves compilation/linking; the physical-device
  green check is completed by the developer via the hand-off checklist.
